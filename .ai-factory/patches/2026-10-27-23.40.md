# Исключение внедрённого traceparent ломало check; аллокация лога агента без logger; лишний клиент в тесте

**Date:** 2026-10-27 23:40
**Files:** src/core/transport.ts, src/core/client.ts, test/unit/client-api.spec.ts, test/unit/client-cache.spec.ts
**Severity:** medium

## Problem

- Если внедрённый `traceparent()` бросал исключение, `check`, `permissions` и `raw.*` отклонялись обычным `Error` (`Error: tracer broken`), хотя §5.1 обещает наружу только `PlatformUnavailableError` и `PlatformContractError`. Баг трассировки превращался в отказ авторизации.
- Каждый `check` агента собирал объект `results` для debug-лога, даже когда `logger` не передан: `logger?.debug(...)` пропускает только вызов, а аргумент всё равно строится. Это лишняя аллокация на горячем пути NFR-1.
- Тест «AC-19: токен после clear()» строил лишний клиент `t` ради его `fetch` и часов, а `handler` второго клиента был мёртвым.

## Root Cause

- Внедрённые колбэки (`traceparent`, а также `clock`, `fetch`, `logger`) считались надёжными. Ошибки транспорта классифицировались только для `fetch`, а вызов `traceparent()` стоял вне `try`.
- Объект `results` строился отдельной инструкцией (`const results = Object.fromEntries(...)`) до `logger?.debug(...)`. Опциональная цепочка отменяет только сам вызов, а предшествующая инструкция выполняется всегда.
- Тестовый помощник `createTestClient` не умел принимать `tokenProvider`, построенный от его же заглушки, и тест обошёл это вторым клиентом.

## Solution

- В `transport.ts` добавлен `traceparentFor(endpoint)`: исключение колбэка ловится, запрос уходит без заголовка, пишется `logger?.debug({ endpoint, reason }, 'traceparent failed, header omitted')`. Регрессионный тест `AC-19: traceparent бросает → запрос ушёл без заголовка traceparent, решение получено` до исправления падал с `Error: tracer broken`, после — зелёный.
- В `client.ts` блок лога решения агента выполняется только при `logger !== undefined`.
- Тест токена строит одного клиента через `createFetchStub`, `createClock` и `createPlatformAuthzClient` напрямую.

## Prevention

- Каждый внедрённый пользовательский колбэк в публичном API — недоверенный код. Его исключение ловится на границе и переводится в ошибку пакета или в безопасное поведение по умолчанию, а тест проверяет «колбэк бросает».
- На горячем пути (NFR-1) данные для лога строятся только внутри `if (logger !== undefined)`, а не перед `logger?.…`.
- Тест строит ровно те объекты, которые проверяет. Если помощник мешает — вызывать фабрики напрямую.
