# tenant подделки Platform не проходил схему события Platform

**Date:** 2026-10-28 00:34
**Files:** src/testing/fake-platform.ts, test/unit/fake-platform.spec.ts, test/unit/require-permission.spec.ts
**Severity:** medium

## Problem

`createFakePlatform` по умолчанию брал `tenant` компании равным `tenantId`. Для типичного `tenantId` вида `org_acme` конверт `policyChanged` нёс `tenant: 'org_acme'`, а схема Platform (`$defs.slug`, `^_?[a-z0-9][a-z0-9-]{0,48}$`) такое значение отвергает. Явный неверный `tenant` в `companies` принимался молча. Пакет это не ловил: zod ядра намеренно мягкий (§5.3), а тесты использовали `tenantId`, совместимые со slug. Попутно тест AC-10 «Platform не вызывается при TypeError объявления» проверял подделанный `fetch`, который не был связан ни с одним клиентом, то есть ничего не проверял.

## Root Cause

PRD v1.9 задал умолчание `tenant = tenantId`, не сверив его со схемой конверта. План заметил расхождение, но закрыл его предупреждением в TSDoc вместо требования. Тесты подобрали входные данные под это допущение (`T = 'org-acme'`) и потому реальный случай `org_acme` не проверяли.

## Solution

Ревизия требований r4 (PRD v1.10): `tenant` по умолчанию — slug из `tenantId` (строчные буквы, символ вне `[a-z0-9-]` → `-`, срез до 49). Явный `tenant` проверяется шаблоном Platform при создании подделки, иначе — `TypeError` с именем поля `companies.tenant`. Регрессионные тесты AC-8a: `org_acme` → `org-acme`, конверт проходит ajv; длинный и смешанный `tenantId` нормализуется; `Bad_Slug` → `TypeError`. Тест AC-10 теперь объявляет классы с `@RequirePermission()` и `@RequirePermission('')` и проверяет пустой `fake.calls()`.

## Prevention

- Значение, которое подделка кладёт в контракт Platform, проверять схемой Platform в тесте на реалистичных входных данных, а не на заранее «удобных».
- Расхождение с контрактом, найденное при планировании, закрывать правкой требований, а не предупреждением в TSDoc.
- Тест «X не вызывается» должен наблюдать тот же объект, через который X мог бы произойти.
