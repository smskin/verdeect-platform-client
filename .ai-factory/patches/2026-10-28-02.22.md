# Слой C: неограниченные ожидания стенда и исключение из consume-колбэка

**Date:** 2026-10-28 02:22
**Files:** test/contract/support/platform-image.ts, test/contract/support/platform-stand.ts, test/contract/support/broker.ts, vitest.contract.config.ts, test/contract/ac-13-catalog.spec.ts, test/contract/ac-14-revocation.spec.ts, test/unit/contract-broker.spec.ts, Makefile
**Severity:** low

## Problem

Ревью E3 (`/aif-review +check`):
- зависшая `docker build` или зависший `GET /ok` подвешивали `make test-contract` без ошибки, хотя §7 п. 9 требует ограниченных ожиданий;
- сообщение `platform.policy.changed`, которое не JSON или без `data`, бросало `SyntaxError` / `TypeError` прямо в consume-колбэке amqplib — прогон падал непонятным исключением вместо сообщения AC-15 (C) «Platform изменил схему — обновить копию».

## Root Cause

- Неверное допущение: `hookTimeout` в `vitest.contract.config.ts` считался пределом для globalSetup. Vitest вызывает `globalSetup.setup` без таймаута (`vitest/dist/chunks/index.*.js`, `await globalSetupFile.setup?.(this)`), поэтому сборка без `timeoutMs` и `fetch` без `signal` не были ничем ограничены.
- Разбор сообщения доверял форме конверта: `JSON.parse` и деструктуризация `envelope.data` шли до проверок ajv/zod, а именно эти проверки должны ловить изменение схемы Platform.

## Solution

- `docker build` — `runProcess(..., { timeoutMs: 900_000 })`, код 124 называет предел; `GET /ok` — `signal: AbortSignal.timeout(2_000)`; комментарий `hookTimeout` — по факту (ограничивает `beforeAll`).
- Разбор вынесен в чистую `inspectPolicyChanged(content)`: try/catch вокруг `JSON.parse` (запись с `ajvErrors: ['не JSON: …']`, `zodValid: false`), ajv и zod — до чтения `data`, `data` — через `?.`. `nextPolicyChanged` выбирает только сообщения с `data` (тип `PolicyChangedEvent`). U-тест `test/unit/contract-broker.spec.ts` без Docker.
- Попутно: `pack-check` без пререквизита `build` (`pack:check` собирает сам), служебные логи перенесены из `.ai-factory/plans/.ai-factory/logs/` в `.ai-factory/logs/`.

## Prevention

- В globalSetup Vitest каждое ожидание ограничивать само: `timeoutMs` у дочерних процессов, `AbortSignal.timeout` у `fetch`, дедлайн у опросов. `hookTimeout`/`testTimeout` его не покрывают.
- Колбэк брокера не должен бросать: данные извне сначала проверяются схемой, а нечитаемое сообщение превращается в запись с ошибкой, которую видит assertion теста.
- Логику колбэка держать в чистой функции, чтобы её можно было проверить в слое U без Docker.
