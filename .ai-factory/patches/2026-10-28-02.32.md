# Слой C: тег [FIX] в постоянных логах, завышенный hookTimeout, неполная карта AGENTS.md

**Date:** 2026-10-28 02:32
**Files:** test/contract/support/platform-image.ts, test/contract/support/broker.ts, vitest.contract.config.ts, AGENTS.md
**Severity:** low

## Problem

Повторное ревью E3 (`/aif-review +check`):
- предупреждения слоя C печатались как `[contract] [FIX] …` — второй префикс сверх соглашения плана (`[contract]`);
- `hookTimeout: 900_000` после уточнения комментария покрывал только `beforeAll`, а там всё ограничено изнутри (5 с и 30 с) — зависший хук ждал бы 15 минут;
- в `AGENTS.md` не было нового `test/unit/contract-broker.spec.ts`.

## Root Cause

- Тег `[FIX]` пришёл из раздела логирования скилла `/aif-fix`, который предполагает временные отладочные строки. Здесь логи постоянные, и у проекта уже есть свой префикс области.
- Значение `hookTimeout` выбирали под сборку образа в globalSetup (ошибочное допущение из прошлого патча). Комментарий исправили, а значение по инерции оставили.
- Файл добавили в ходе исправления, а карту репозитория не обновили.

## Solution

- `[FIX]` убран: остался только `[contract]`.
- `hookTimeout: 120_000` — с запасом покрывает один `prepareMember`.
- В `AGENTS.md` добавлена строка `contract-broker.spec.ts  # AC-15 (C): разбор platform.policy.changed без Docker`.

## Prevention

- В постоянный код этого репозитория `[FIX]` не добавлять, только префиксы областей (`[contract]`, `[publish]`, `[package-check]`).
- Если меняется обоснование лимита, пересчитывать и само значение, а не только комментарий.
- Каждый новый файл в `test/` сразу вносить в дерево `AGENTS.md`.
